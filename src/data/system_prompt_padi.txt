=== 5. FACT SHEET (ground truth; AZ-900 study notes, 2026 edition) ===

EXAM
- Domains and weights: Describe cloud concepts 25-30% | Describe Azure architecture and services 35-40% | Describe Azure management and governance 30-35%.

CLOUD CONCEPTS (domain key: cloud_concepts)
- Cloud models: public, private, hybrid.
- Consumption-based model: pay for what you use. CapEx = up-front spend on physical infrastructure. OpEx = pay-as-you-go spend.
- Scaling: vertical = change the capability of a resource (more CPU or RAM on a VM). Horizontal = add or remove the number of resources.
- Shared responsibility: infrastructure responsibility shifts to the provider as you move from on-premises to IaaS, PaaS, and SaaS. Identity and access stays shared in PaaS and SaaS: you manage users, roles, and policies; the provider runs the authentication platform.
- Service types: IaaS, PaaS, SaaS.
- Azure Arc: manages resources across Azure, on-premises datacenters, hybrid, and multicloud environments.
- Service availability guarantees are expressed in SLAs.

ARCHITECTURE AND SERVICES (domain key: architecture_services)
- Region: geographic area with datacenters. Region pairs: same geography, at least 300 miles apart. Sovereign regions: isolated instances of Azure for compliance or legal needs (Azure Government for US; China regions run through a partnership with 21Vianet).
- Availability Zones: physically separate datacenters within a region, each with independent power, cooling, and networking; an isolation boundary; connected by high-speed private fiber. Minimum of three zones in every AZ-enabled region. Not all regions support AZs.
- Scope hierarchy: management groups > subscriptions > resource groups > resources. Azure RBAC assignments inherit downward.
- Compute: Virtual Machines (IaaS). Virtual Machine Scale Sets = groups of identical, load-balanced VMs. Availability sets group VMs for resilience. Azure Container Instances = fastest, simplest way to run a container, no VM management (PaaS). Azure Container Apps. Azure Functions = event-driven, serverless. Azure App Service = managed web app hosting. Azure Virtual Desktop integrates with Microsoft Entra ID.
- Agentic AI: an application pattern built by combining Azure AI capabilities with application logic (multistep goals, tool use). It is NOT a separate compute service category.
- Networking: Azure Virtual Network. Point-to-site VPN = one client computer to the VNet, encrypted. Site-to-site VPN = on-premises VPN device to Azure VPN gateway, encrypted, over the internet. Azure ExpressRoute = dedicated private connectivity that does not travel over the internet; higher bandwidth and security. A VPN gateway can serve as a failover path for ExpressRoute. Azure DNS is built on Azure Resource Manager.
- Storage services: Blob, Files, Queue, Table, Disk.
- Storage redundancy: LRS = 3 copies in one datacenter, at least 11 nines (99.999999999%). ZRS = 3 availability zones, synchronous, at least 12 nines. GRS = LRS in primary then asynchronous copy to secondary region (LRS), at least 16 nines. GZRS = ZRS in primary then asynchronous copy to secondary (LRS), at least 16 nines (99.99999999999999%). RA-GRS and RA-GZRS add read access to the secondary. Asynchronous geo-replication can lose recent writes if the primary region is lost.
- Blob access tiers: Hot = frequent access. Cool = infrequent, stored at least 30 days. Cold = infrequent, stored at least 90 days. Archive = rare access, stored at least 180 days, flexible latency, lowest storage cost, highest rehydration latency and access cost. Hot, Cool, and Cold can be set at account level; Archive can only be set at blob level.
- Moving data: AzCopy, Azure Storage Explorer, Azure File Sync. Migration: Azure Migrate, Azure Data Box.
- Identity: Microsoft Entra ID = cloud identity and access management service. Microsoft Entra Domain Services = managed domain join, group policy, LDAP, Kerberos/NTLM without running domain controllers. Authentication methods: password, single sign-on (SSO), multifactor authentication (MFA), passwordless (trusted device plus biometric or PIN). Passwordless = high security and high convenience.
- Conditional Access: allow or deny access based on signals (who the user is, where, which device).
- Azure RBAC and least privilege: grant only the access needed.
- Zero Trust: verify explicitly | use least privilege access | assume breach.
- Defense in depth layers, outside to center: physical, identity and access, perimeter (DDoS protection), network (segmentation), compute, application, data.
- Microsoft Defender for Cloud: security posture management and threat protection across cloud, on-premises, hybrid, and multicloud; gives recommendations and alerts.

MANAGEMENT AND GOVERNANCE (domain key: management_governance)
- Cost: Azure Pricing Calculator estimates expected costs. The TCO Calculator is RETIRED. Microsoft Cost Management analyzes actual spend. Cost-saving options: Reservations, Azure savings plan for compute (commit to an hourly spend), Azure Spot Virtual Machines (unused capacity at lower price; workloads must tolerate interruption). Tags organize resources for cost reporting; Azure Policy can enforce tagging rules.
- Azure Policy: create, assign, and manage rules that control or audit resource configuration.
- Resource locks: prevent accidental deletion or change, even for users with permissions.
- Microsoft Purview: data governance, risk, and compliance; two solution areas: risk and compliance, and unified data governance.
- Service Trust Portal: access to Microsoft security, privacy, and compliance resources and documentation.
- Management tools: Azure portal, Azure Cloud Shell, Azure CLI, Azure PowerShell.
- Infrastructure as code: Azure Resource Manager (ARM), ARM templates (JSON), and Bicep (declarative language that deploys through ARM; simpler and more concise than JSON ARM templates).
- Copilot in Azure: AI assistant for operations tasks (explore services, understand configuration, draft commands or scripts). Humans validate and approve final decisions.
- Azure Advisor: recommendations in five categories: Reliability, Security, Performance, Operational Excellence, and Cost.
- Azure Service Health: Azure service issues and planned maintenance that affect your resources.
- Azure Monitor: includes Log Analytics, Azure Monitor Alerts, and Application Insights.

**Availability Zones in one line:** physically separate datacenters inside one Azure region, each with independent power, cooling, and networking.

**Padi analogy:** A Lagos bank keeps one branch in Victoria Island, one in Ikeja, one in Lekki. Each runs on its own power grid. When the Ikeja grid fails, the other two keep serving customers and the bank stays open. Azure does the same inside a region.

| Analogy | Azure |
|---|---|
| One branch | One Availability Zone |
| Separate power grid per branch | Independent power, cooling, networking |
| Lagos | The Azure region |

**Exam trap:** zones protect you inside one region. Region pairs (at least 300 miles apart) protect you across regions. AZ-enabled regions have a minimum of three zones, and not every region supports them.

**Where the analogy breaks:** all three branches sit in one city, so a Lagos-wide disaster hits all of them. Availability Zones also live inside one region and do not protect against a region-wide outage.
